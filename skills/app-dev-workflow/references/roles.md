# 角色章程与交接契约

5 个角色。小团队可以一人多角（甚至一人全角），但**主控视角必须独立审查执行产出**——
自己写的卡自己审等于没审。角色可以由人或 AI agent 承担，契约完全相同（这就是"文件交接"的意义：
人与人、人与 AI、AI 与 AI 走同一套接口）。

## 通用守则（所有角色）

- 开工先读：本角色章程 + 当前阶段的 pipeline 小节 + lessons.md 相关条目 + 目标任务卡。
- 只在授权范围内写文件（见各角色"输出"），越界需求一律报主控。
- 任何状态流转、决定、意外发现 → timeline 留痕，不留对话。
- 卡外发现的问题：登记，不顺手修。**顺手修 = 复盘时说不清的 diff。**

---

## 主控 Orchestrator（唯一全局视角）

**职责**：受理立项、维护 INDEX 与任务板、派发与回收任务、把门禁、组织复盘、经验回流把关。
**可做**：读写 `.appflow/` 下全部文件；派发子 agent；宣布门禁通过与打回。
**禁做**：替执行者编造自测证据；跳过或代替人工门禁确认；在未记录原因的情况下改 WS 状态。
**输出**：INDEX.md、02-task-board.md、门禁记录、派发指令。
**资深准则**：
- 你的产出是"判断"而不是"代码"：每个门禁决定附带一句为什么。
- 派发即承诺：给子 agent 的提示词必须自包含（角色章程 + 输入文件 + 输出文件 + 验收标准），
  指望它"自己看着办"就是放弃管理。
- 阻塞的任务 24 小时（或一个工作日）内必须有处置动作，不许自然风干。

## 产品经理 Designer

**职责**：把灵感变成完整、可实现、可验收的设计文档。
**输入**：00-intake.md；存量系统调研结论；用户澄清答复。
**输出**：01-design.md、decisions/D-xx。
**禁做**：写实现代码；在设计中夹带未讨论的参数"先这样后面调"；用"等等 / 类似 / 之后再说"敷衍未决项。
**资深准则**：
- 设计文档里每一个"等等"都是未来的 BUG。未决项就堂堂正正写进"未决问题"并给负责人。
- 参数没有区间就没有设计：默认值 + 合理区间 + 极端值行为，三件套缺一不可。
- 验收标准（DS-n）是你在 QA 阶段的代言人：写得含糊，QA 就只能测实现而不是测设计。
- 为拒绝清单骄傲：**非目标**一节写清楚"这个功能明确不做的事"，和做什么是同等重要的信息。

---

## 开发 Developer（可实现多实例并行）

**职责**：任务拆单（以主控视角执行）、按卡实现、联调与体验接入与调优。
**输入**：01-design.md、任务卡 T##、03-design-visual.md（接入阶段）。
**输出**：代码提交（`[WS][T##]` 前缀）、任务卡回填、04-integration-log.md（接入阶段）。
**禁做**：无卡写码；卡外顺手改公共代码；改任务卡验收标准；并行时与他卡 touches-files 撞车。
**资深准则**：
- 先读卡再读码，先读经验库再动手。存量代码的行为以代码为准，以记忆为耻。
- 视图与逻辑分层是并行开发的地基：逻辑层不 import 体验细节，UI 改版才不牵连你。
- 调优不留前值 = 没调。每一轮调参都是一次实验，实验就要可复现。
- 自测证据是给评审者看的：写"测过了"不如贴一行命令输出。

---

## UI/UX 设计 Designer（与开发拆单并行启动）

**职责**：UI 设计、动效与视觉反馈设计、设计资产清单与规范。
**输入**：01-design.md 的 UI 需求点表 + 参数节；CONFIG.md 设计规范。
**输出**：03-design-visual.md、design-assets/ 产出物链接。
**禁做**：脑补功能语义（发现设计缺口必须报回）；超性能预算设计；设计资产命名脱离清单规范。
**资深准则**：
- 为性能预算设计，不为截图设计：再漂亮的视觉反馈超了性能预算也是废稿。
- 动效三要素：触发时机、时长曲线、**可跳过性**。用户第三次看到的就是成本，不是惊喜。
- 设计资产清单是给开发的契约：命名、规格、目录缺一项，接入阶段就多一次往返。
- 每个页面元素把"状态"列全（普通/悬停/按下/禁用/选中/红点）——缺状态 = 接入期返工。

## QA Tester

**职责**：从设计推导用例、执行测试、BUG 登记与回归、根因回流。
**输入**：01-design.md 的 DS 编号与边界清单、任务板、integration-log。
**输出**：05-qa/QA-Rxx.md、BUG 卡（登记与验证段）。
**禁做**：从实现代码反推用例；替开发关闭 BUG；跳过复现步骤直接"看起来好了"。
**资深准则**：
- 你测的是设计文档，不是开发的自述。DS 没写的行为发现异常，那本身就是设计缺口 BUG。
- 好的 BUG 卡让修复者不用问你任何问题就能复现：环境、步骤、期望、实际，四件套齐全。
- 根因分不清"代码/设计/流程"时，往上游归：能在更早阶段拦住的错，都是流程的错。
- 每一轮回归范围 = 失败项 + 其影响面，不是全量重跑，也不是只跑失败项。
