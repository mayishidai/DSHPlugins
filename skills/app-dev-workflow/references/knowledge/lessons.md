**写入规则**：新条目编号 = 当前最大 L-### + 1，永不复用；与既有条目同义时不重复开条，
在旧条目下追加"补充案例"。通用判定：去掉项目名仍成立 → 本库；否则入项目的 `.appflow/LESSONS.md`。
每条必须带来源（WS / BUG / 复盘）。修改本文件须登记 skill 的 CHANGELOG.md。

**条目格式**：

```

- **教训**：错在哪、代价是什么

```

## L-001 | 参数无边界 = 把坑留给 QA
- 2026-09-13 / 设计 / 产品经理 / `阶段:设计` `标签:参数` / 来源：种子（初始示例，待真实复盘覆盖）
- **情境**：设计文档只写了"列表按更新时间排序"，没写分页大小、空数据与超大数据量时的行为。
- **教训**：实现各自解释边界，QA 阶段刷出离谱参数，三方对"是不是 bug"争论两天。
- **对策**：设计文档中每个参数必须给三件套——默认值、合理区间、极端值行为（G1 检查项）。

## L-002 | 文档里的"等等"就是未来的 BUG
- 2026-09-13 / 设计 / 产品经理 / `阶段:设计` `标签:文档质量` / 来源：种子
- **情境**：设计文档多处出现"等等""之后再定""类似 XX 就行"，开发按各自理解填补。
- **教训**：模糊表述在三个角色脑中是三个设计，返工量远超把话写清楚的成本。
- **对策**：含糊处一律显式进"未决问题"（带负责人与节点）；未决 >3 项不得过 G1（门禁项）。

## L-003 | 视图与逻辑必须分卡
- 2026-09-13 / 拆单 / 开发 / `阶段:拆单` `标签:架构` / 来源：种子
- **情境**：订单列表的状态逻辑与页面组件写在同一张任务卡、同一批文件里，UI/UX 设计中途改版。
- **教训**：改版牵连逻辑重测，并行开发也做不起来——UI/UX 设计与开发无法各走各路。
- **对策**：拆单时数据/逻辑层与体验层（UI 绑定、动效挂接）强制分卡分文件（拆单原则）。

## L-004 | 并行任务改同一配置表必撞车
- 2026-09-13 / 实现 / 开发 / `阶段:实现` `标签:并行` / 来源：种子
- **情境**：两张并行任务的 touches-files 都包含全局配置文件，后提交者覆盖了前者的字段。
- **教训**：公共资源上的"并行"实际是串行+互相破坏。
- **对策**：公共配置文件 / 公共组件默认高危，涉及它们的卡一律先行串行（互斥检查规则）。

## L-005 | 没有前值记录的调优等于没调
- 2026-09-13 / 接入 / 开发 / `阶段:接入` `标签:调优` / 来源：种子
- **情境**：交互体验调优会上反复改参数，一周后想回到"那天交互体验最好的版本"，没人记得参数。
- **教训**：不可复现的调优在版本迭代后全部归零。
- **对策**：调优记录表强制四要素：参数/前值/后值/理由（+观察效果），缺前值视为违规（铁律 3 延伸）。

## L-006 | 用例从设计推导，不从实现反推
- 2026-09-13 / QA / QA / `阶段:QA` `标签:测试` / 来源：种子
- **情境**：测试同学直接照着实现代码写用例，代码里没处理的分支自然也没被测到。
- **教训**：用例覆盖度上限被实现锁定，设计里写明但实现遗漏的行为全部漏网。
- **对策**：每条用例必须溯源 DS 编号或边界清单条目；QA 发现 DS 没写的行为异常，按设计缺口报 BUG。

## L-007 | QA 期接受需求变更 = 回归范围失控
- 2026-09-13 / QA / 主控 / `阶段:QA` `标签:变更管理` / 来源：种子
- **情境**：QA 第三天"顺手"加了个小需求，已跑完的用例全部失去效力但没人重跑全部。
- **教训**：一次小变更让全部已通过结果作废，发布延期且没人说得清测过什么。
- **对策**：QA 期设计冻结；变更走 D-xx 例外审批并明确回归范围，或转入新 WS（门禁与禁令）。

## L-008 | 估时偏差大的任务必藏流程问题
- 2026-09-13 / 复盘 / 主控 / `阶段:复盘` `标签:估算` / 来源：种子
- **情境**：复盘时发现超时最多的几张卡，根因都不是"写得慢"，而是设计缺口或依赖未就绪。
- **教训**：估时偏差是流程问题的温度计，不归因就会在下个 WS 原样复发。
- **对策**：偏差 >50% 的任务复盘强制归因（G7 检查项），归因结论回写拆单原则或经验库。
