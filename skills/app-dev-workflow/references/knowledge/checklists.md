# 门禁清单（G0–G7）

判定规则：**全项满足才通过**；任一不满足 → 打回并记录到 timeline（打回不算失败，
带记录的打回正是复盘设计资产）。G1 与 G5 默认需人工确认（CONFIG.md 可改）。
清单本身随经验增长：lesson 修订检查项时在此追加（并登记 CHANGELOG）。

## G0 受理完成 → 允许进入设计
- [ ] 原始需求原话已保留（未改写）
- [ ] 背景与动机已记录
- [ ] 澄清问题已一次性问过（答复或未决都有记录）
- [ ] 类型与规模已定（feature/bugfix/optimization/refactor × S/M/L）
- [ ] 已查 INDEX 做过查重，关联 WS 已互链
- [ ] 初步验收标准能demo级说清"做到什么算成"

## G1 设计评审通过 → 允许拆单与 UI/UX 设计（人工）
- [ ] 三方视角各过一遍：产品经理完整性 / 开发可行性 / UI/UX 设计可做性
- [ ] "非目标"一节已写（明确不做的事）
- [ ] 现状与约束来自实际调研（非臆测）
- [ ] 所有参数三件套齐全：默认值/区间/极端行为（L-001）
- [ ] 无含糊表述残留；未决问题 ≤3 且各有负责人与节点（L-002）
- [ ] 边界与异常逐条有处理方式
- [ ] 依赖系统影响面已被相关模块确认
- [ ] UI 需求点表完整（UI/UX 设计唯一输入接口）
- [ ] 性能预算有值或有"未定+跟进人"
- [ ] 验收标准已编号 DS-n 且可执行验证

## G2 拆单通过 → 允许进入实现
- [ ] 设计文档每节都能指到任务（或书面"不适用"）
- [ ] 每卡：验收标准 + touches-files + 估时（乐观/现实）+ 依赖标注
- [ ] 粒度合规（≤2 人日，超必拆）
- [ ] 视图与逻辑分卡（L-003）；公共底座卡排最前
- [ ] DAG 无环；并行组内 touches-files 无交集（L-004）
- [ ] 任务板波次规划完成；初始状态正确（ready/backlog）

## G2' UI/UX 设计通过 → 产出可供接入
- [ ] UI 需求点表逐条对齐（全覆盖或缺口已报主控）
- [ ] 每页面元素状态列全（普通/悬停/按下/禁用/选中/红点）
- [ ] 每条动效：触发时机/时长/曲线/可跳过性；每条视觉反馈：触发点/时长/预算/层级
- [ ] 设计资产清单命名与目录符合 CONFIG.md 规范
- [ ] 预算合计不超 01-design.md §10
- [ ] 开发配合需求已回流主控

## G3 单卡完成（逐卡过）
- [ ] 验收标准逐条满足且有证据（非口头"测过了"）
- [ ] 无未声明的范围扩张（卡外改动为零或已报备）
- [ ] 提交信息带 `[WS][T##]` 前缀
- [ ] 任务卡已回填：变更文件、commit hash、实际耗时、踩坑备注
- [ ] timeline 有该卡状态流转记录

## G4 接入调优完成 → 允许进入 QA
- [ ] 接入清单全勾（页面/动效/视觉反馈/空态逐项）
- [ ] 调优记录每条含前值/后值/理由/效果（L-005）
- [ ] 性能与交互体验实测对照预算，偏差有登记或 D-xx 决策
- [ ] 占位资源全部显式登记（无隐式占位）

## G5 发布验收通过 → 允许合入（人工）
- [ ] 用例 100% 执行且每条溯源 DS/边界项（L-006）
- [ ] P0/P1 BUG 清零
- [ ] P2/P3 每个有处置决定（修 / 延期带去向）
- [ ] 回归完成（失败项 + 影响面）
- [ ] QA 期间无未审批的设计变更（L-007）
- [ ] 根因=流程 的 BUG 已产出经验条目或检查项修订（强制回流点）

## G6 合入完成
- [ ] G0–G5 全部有记录地通过（timeline 可查）
- [ ] PR/merge 描述含 WS 路径与结果摘要；WS 与 merge commit 互查可达
- [ ] WS 无 TODO 级未决（或已转卡/BUG）
- [ ] 复盘已排期（WS 不得在复盘前关闭）

## G7 复盘完成 → 允许关闭 WS
- [ ] 交付结果、数据（估时/BUG 分布/并行度/门禁回顾）齐全
- [ ] 估时偏差 >50% 的任务已归因（L-008）
- [ ] 三问完成；改进项每条有负责人与去向
- [ ] ≥1 条经验入库，或书面说明为何没有
- [ ] 涉及 skill 的修改已在 CHANGELOG.md 登记
- [ ] timeline 完整覆盖 WS 全生命周期
