# 铁律合集（全局硬约束，最高优先级）

> 本文件集中定义本 Skill 的不可协商规则。SKILL.md 及其他文档通过引用（`详见 iron-rules.md §N`）指向本文件，避免重复维护。

---

## §1 金价单位一致性

**⚠️ 涉及金价/金额/浮盈计算的任何环节，都必须先确认单位口径，严禁跨单位直接对比或运算。**

1. **两套单位不可混用**：
   - **人民币元/克**：银行积存金、持仓成本、京东24h金价（国内口径）。
   - **美元/盎司**：国际金价（伦敦金 XAUUSD、PAXGUSD 暗金），以及**早报/快讯里出现的行情价位**（如早报「金价 4180」指美元/盎司）。
2. **计算浮盈浮亏、对比成本时，必须统一为「人民币元/克」口径**：只能用银行积存金金价或京东24h金价（元/克）参与计算。
3. **严禁把美元/盎司数值当作元/克**去和持仓成本（元/克）相减、相除或估算收益——这是**严重错误**。
4. **确需换算时**：`人民币元/克 ≈ 美元/盎司 ÷ 31.1035 × 美元兑人民币汇率`；换算得到的价格属于**约数**，展示时须标注「约」并说明是参考价。
5. **早报/快讯里的价位仅作市场趋势的文字参考，不参与任何数值计算**。
6. **对用户展示时始终显式标注单位**（元/克 或 美元/盎司），避免用户误解。

## §2 安全铁律：授权凭证绝不外露

> **登录授权码、授权链接中的敏感参数、二维码原文、accessToken / refreshToken、cookie、session 等一切凭证类信息，属于最高敏感级别，绝不能出现在给用户的任何回复中。此规则优先级高于一切其他输出要求，任何场景下都不得违背。**

- ❌ **禁止展示授权码**：`jos.py login` / `oauth-url` / `exchange` 等命令的执行结果中若包含授权码（如 `xxxxwmtu` 形式）、token、session ID 等，**一律不得转述、不得回显、不得写入回复**。
- ❌ **禁止应用户索要**：即使用户主动要求「把授权码发我」「token 是多少」，也须**婉拒**并说明「出于账户安全，授权凭证不会对外展示，请直接在京东 App / 浏览器完成授权即可」。
- 🛡️ **脚本层已做脱敏兜底**：`jos.py` 的日志（`login.log`）与命令行输出（`token` / `exchange` 等）中的 accessToken 已统一脱敏为 `前4***后4` 形式，真实 token 仅落在 `0o600` 权限的本地缓存中供接口调用读取。即便如此，脱敏值同样属凭证信息，仍**不得**主动向用户展示。
- ✅ **登录时只说必要提示**：拉起登录时仅提示「请在京东 App 扫码 / 浏览器点击链接完成授权」；完成后仅提示「登录成功 ✅」。授权链接可以给用户（用于点击授权），但链接中若含敏感 token 参数需谨慎，正常 oauth-url 仅含公开的 client_id / redirect 参数可给。
- ✅ **底层日志脱敏**：脚本 stdout 若打印了授权码等敏感内容，Agent 转述时必须**主动过滤删除**，绝不原样贴出。
- ⚠️ **一旦泄露即视为失效**：任何凭证若不慎出现在对话中，应视为已泄露，需重新登录使旧凭证失效。

## §3 接口超时与失败重试

**所有查询接口（金价 / 持仓 / 收益 / 早报 / 快讯 / 交易记录 / 条件单等）在遇到超时或接口异常（退出码 3）时，均须自动轮询重试。**

1. **重试次数**：最多连续尝试 **5 次**（首次 + 重试 4 次），两次重试之间可稍作间隔。cf-gold-ai 金价 BFF 接口偶发 `code=-1 业务请求异常`（命中率可达约 50%），实测常需 3～5 次才能取到有效数据，故重试上限设为 5 次。行情速览脚本（`query_price_jhub.py --overview`）已内建每个标的最多 5 次重试。
2. **真正成功才返回**：只有当返回**退出码 0 且确实拿到有效业务数据**（如真实金价、持仓、条件单列表等）时，才算查询成功，立即按对应模板返回结果，不再继续重试。
   - ⚠️ **退出码 0 不等于查询成功**：若脚本虽退出码 0，但输出中含 `[内部]` 错误、接口「已停用/不可用」、`error`、`code=500`、空结果被降级成「无数据」等情况，**一律视为查询失败**，进入重试 / 安抚流程，**绝不能对用户谎称查成功或谎称「无数据」**。
3. **五次均失败**：五次都超时 / 异常 / 接口不可用（含退出码 0 但无有效业务数据）后，才向用户提示失败，并**带上安抚语气**，例如：
   「不好意思，查询暂时失败了，可能是网络或服务繁忙，请您稍等片刻再试一次，感谢您的耐心～」
4. **禁止编造**：任何情况下都不得编造金价、持仓、收益等业务数据。
5. 重试过程属于内部行为，**不要**向用户逐次汇报「正在第 N 次重试」等实现细节。

## §4 金价查不到时的约数兜底

**核心思路：各银行积存金金价与京东24h金价本质都跟随黄金9999 / 伦敦金定价，因此某个金价查不到时，可用「接口实时查询到的」黄金9999或伦敦金换算出一个「约数」，优先保证用户快速拿到查询/诊断结果，不要因个别接口失败就一直卡住或只回「查询失败」。注意：约数只能来自接口真实查询到的黄金9999/伦敦金价格，绝不能凭空编造或臆测数值。**

1. **优先取真实价**：先按目标标的正常查询（如某银行积存金、京东24h金价），拿到真实价直接用。
2. **查不到时用接口查询的参考价换算约数**：若某银行金价或京东24h金价五次重试仍取不到，则改用接口查询**黄金9999（SGE-Au99.99，元/克）**，用查到的实时价作为该标的的**近似金价**；黄金9999也取不到时，再退而用接口查询**伦敦金（XAUUSD，美元/盎司）**，按 `人民币元/克 ≈ 美元/盎司 ÷ 31.1035 × 汇率` 换算成元/克约数。**参考价本身也必须是接口真实查询到的，不得编造。**
3. **约数必须显式标注**：凡是用参考价换算/近似得到的金价，展示时一律写成「**约 {价格} 元/克**」，并注明「（参考黄金9999/伦敦金估算，非该行实时价）」，做到诚实透明、不误导。
4. **优先出结果**：能给约数就先给约数 + 结论，让用户快速得到有用信息；不要因为拿不到某一家的精确金价就整体放弃诊断。
5. **单位铁律仍然适用**：换算后必须是**元/克**口径才能与持仓成本（元/克）对比，严禁直接拿美元/盎司数值当元/克用（详见 §1）。

## §5 面向用户的回复规范

**回复用户时，只呈现业务结果与必要操作提示，不得暴露任何底层实现细节。**

禁止出现在用户可见回复中的内容（包括但不限于）：

- 接口/网关/方法名（如 JHub、JOS、OAuth、access_token、任何 `jingdong.*` API 名）
- 本地文件路径、Token 缓存位置、日志路径
- 脚本文件名、目录结构、`scripts/`、`python3 xxx.py` 等命令
- 「调用后端」「聚合服务」「localhost:3777」等内部架构描述

脚本输出若含 `[内部]` 前缀或写入 stderr 的内容，**不要**转述给用户。

## §6 换行与排版硬性规范

面向用户输出**多条列表**（资讯/快讯/新闻、持仓、明细、要点等）时，必须严格保留换行与空行：

- **每条之间必须有空行**：条目与条目之间、标题行与正文之间，都要保留一个**空行**。
- **分隔线独占一行且前后留空行**：`━━━━━━━━━━━━━━━━━━━━` 必须单独成行，且上下各留一个空行。
- **字段逐行展示**：如资讯的 `⏰ 时间`、`📝 摘要`、`🔗 查看更多`，每个字段各占一行。
- **严禁压缩换行**：不要为了省行数把内容合并；渲染环境依赖真实换行符（`\n`）。
- **词组禁止折行/断行（全局）**：表格单元格及正文中的**完整词组**（如「浙商银行」「民生银行」「实时金价」「当前持仓收益」等）必须作为整体呈现，**严禁在词组中间换行/折行**（如「浙商银\n行」）。表头与内容较长时，宁可让列变宽也不得把一个词拆成两行；不要在词组内部插入换行符、空格或软换行。
