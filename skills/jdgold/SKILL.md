1. **未指定标的 → 输出「黄金行情速览」**：用户只说「查金价」「黄金多少钱」「金价怎么样」等未指定具体标的时，调用 `python3 query_price_jhub.py --overview`（或 `--parse "查询金价"`）输出分组行情速览，**不要只给京东24h金价单条**，也不再回问「请输入要查询的黄金标的」。行情速览含两组：

2. **指定标的 → 单条查询**：标的明确且在支持范围内 → 确保已登录 → 查询 → 按模板返回。
3. **银行维度**：用户指定某银行积存金价（如「民生积存金多少钱」），查询该银行 uniqueCode 对应的金价。
4. **不做跨标的对比**：单独询问某一家银行积存金价格时，只回复该银行金价，**不要拿它与京东24h金价（或其他标的）作对比**，除非用户明确要求对比。
5. **涨跌额兜底**：接口可能不返回涨跌额（raise）字段，脚本已自动用「最新价 − 昨收」兜底计算，直接转述即可。

### B. 查询持仓/收益（须登录）

1. **仅支持当前登录账号**，不支持指定他人账号查询。
2. 用户给出他人账号标识且与当前登录不一致 → 提示「仅支持查询您当前登录账户的信息」。
3. 未登录 → 给出授权链接；优先使用 `--wait-login`，登录后自动续查。
4. **不要编造**持仓或收益数据。

## 模拟交易（买入 / 卖出 / 账户）

> 黄金模拟交易：用虚拟货币「金叶子」进行模拟买卖，练手不涉及真实资金。以下规则约束模拟交易的完整流程。

### 🔴 交易前须用户确认数额（最高优先级 · 不可协商）

- 收到「模拟买入 / 模拟卖出」等交易指令时,**下单前交易数额必须经用户确认**。
- **允许主动推荐数额**:可结合行情分析与账户情况**主动给出一个具体推荐数额**(如「建议买入 10 万金叶子,可以吗?」),但**必须等用户确认后**才下单。
- **禁止**未经确认就自行代填、默认取值、臆测金额或凭上一次数额直接下单。
- 用户明确给出数额,或明确回应「梭哈/全买/全卖/就按你说的」等清晰指令时,**视为已确认**,可直接下单。
- 仅**查询类**操作(账户 / 行情 / 交易记录)可直接执行,无需确认。

### 计价方式

- **买入**：`--trade-unit 1`（按金额，传 `--trade-amount`，单位金叶子）或 `--trade-unit 2`（按克重，传 `--trade-gram`）。
- **卖出**：`--trade-unit 2`（按克重，传 `--trade-gram`）或 `--trade-unit 3`（按比例，传 `--trade-ratio`，范围 0.01–1.00）。

### ⚠️ claw 参数必传

- 所有模拟交易脚本调用（account / buy / sell / kline / time-sharing / records / overview）**必须传 `--claw` 参数**，用于上报客户端类型，随请求以 `x-claw` 请求头发送。

### 交易流程

1. 判登录态（同全局规则），未登录先引导登录。
2. **先做行情分析**（见「投资助手」一节）：**结合近 10 日 K 线（`kline`）与今日实时分时（`time-sharing`）**，判断当前价位处于高位还是低位、给出买卖倾向与推荐金额区间。
3. **推荐并确认数额**:可结合第 2 步分析**主动给出一个具体推荐数额**(金额/克重/比例任选其一,如「建议买入 10 万金叶子」),请用户确认;用户已给数额或明确「梭哈/全买/全卖/按你说的」则视为已确认。
4. 用户给出明确数额后，生成幂等 `--bus-id` 下单。
5. 下单后**必须实查**账户与交易记录反馈结果，**禁止**编造成交数据。

### 📈 模拟交易投资助手（行情分析 + 交易建议）

> 定位：做用户的**模拟交易投资助手**。用户咨询买/卖、或下单前，**主动拉取模拟行情走势并给出分析建议**，帮用户看懂当前是不是好的交易点。

- **拉行情（近 10 日 + 今日实时结合）**：分析**必须同时结合两类数据**——① 近 10 日 K 线（`kline`，`--k-type day --nums 10`）看中期趋势与区间高低点；② 今日实时分时（`time-sharing`，`--type m1/m5`）看今日开盘价、当前价、今日高/低。模拟交易为实时买卖，**判断买卖点须兼顾中期趋势（近10日）与当日盘中位置（实时）**。数据须实查、禁编造。
- **看走势**：算出**近 10 日区间高点/低点** + **今日开盘/今日高/今日低/当前价**，综合判断当前处于中期与当日的相对高低位、趋势方向（上行/下行/震荡）。
- **给建议**：
  - 相对低点 + 趋势企稳 → 倾向**买入**（适合建仓/加仓）；
  - 相对高点 + 趋势走弱 → 倾向**卖出**（适合止盈/减仓）；
  - 高位震荡不明 → 建议**观望**或小额试探。
- **推荐金额**：结合账户可用额度 / 当前持仓，给出**推荐交易金额区间**（如「可用额度的 10%–20%」或具体金叶子数），作为参考。
- **红线不变**:投资助手可**主动推荐具体数额**,但最终下单数额**仍须用户确认**(不违反「交易前须用户确认数额」红线);用户明确「梭哈/全买/全卖/按你说的」等清晰指令时,视为已确认,可直接执行。
- **风险提示**：每次分析结尾附一句「以上为模拟行情分析，仅供参考，不构成真实投资建议」。

### 🤝 全权托管（自动盯盘 · 本地定时脚本执行）

> 用户可授权 Agent「代为盯盘、低买高卖」，通过**本机定时脚本**（macOS launchd）持续轮询金价、按策略自动下单。托管仅限模拟金叶子，不涉及真实资金。

#### 开启托管前的三步（缺一不可）

**① 要授权**：向用户明确说明并取得**显式授权**，禁止未授权就自动下单。授权时约定：
- 标的（默认京东 24h 金价）、单日上限（问用户，可不设）、总托管上限（=账户余额，花完即停）、撤销方式（用户随时可说「停止托管」）；
- 买卖点、单笔克重由 Agent 按「近 10 日 + 今日实时」行情动态判断，无需用户逐项设定。

**② 告知风险**：授权前**必须**说清——
- 「模拟交易不涉及真实资金，但**投资有波动，不保证只赚不赔**」；
- 说明**采用的投资策略**（如「近 10 日 + 今日实时结合，低位分批建仓、高位分批止盈」）。

**③ 告知「什么情况下会停」（外部条件，必须逐条讲清，否则用户会误以为一直在跑）**：
- **登录授权会过期**：开启托管时用**大白话**告知用户当前授权**还能托管约 X 小时**（读 `jos.py token --json` 的剩余秒数换算，不要说「token」这种术语）。⚠️ 登录有效期**通常只有几小时（约 8 小时）**，过期后**无法自动续期**（续期功能后端未上线），脚本立即停止并通知用户，用户须**重新登录一次**（需开浏览器人工授权，Agent 无法代点）。因此须提醒用户「托管前留意剩余时长，可能当天就需再登录一次」。
- **关机 / 电池睡眠会停**：脚本靠 launchd 跑，**电脑关机一定停**；靠电池合盖熄屏会随系统睡眠而暂停（醒来补跑）。须提醒用户「想稳定托管请**插电 + 不关机**」。
- **退出 AI 软件不影响脚本**：launchd 是独立系统服务，退出 JoyCode / 关掉对话，定时脚本照常运行；仅「Agent 主动分析、对话推荐」这类需 Agent 在场的动作会中断，纯脚本按预设策略下单不受影响。

用户三项全部同意后，才在**用户终端本地**部署并启动脚本。

#### 执行方式（本地定时脚本 `sim_autotrade.py` + launchd）

- 脚本单次执行逻辑：① 判登录态（`jos.py token`，过期即停 + 通知，不静默失败）→ ② 拉近 10 日 K 线 + 今日实时分时（`--json`）算买卖点 → ③ 命中低买/高卖且在总上限（=实查余额）/单日上限（如设）/冷却期内 → 动态定克重下单（幂等 bus-id）→ ④ 成交/跳过写本地日志 + 通知用户 → ⑤ 余额不足或达上限则停。
- **通用默认规则**（写进脚本，所有用户一致）：总托管上限 = 账户余额花完即停；单日上限可不设（不设则一直托管到余额花完或用户叫停）；轮询频率 30 分钟；冷却期 60 分钟；token 过期即停 + 通知；仅模拟金叶子。
- **个性化配置**（用户覆盖默认的具体数值，如单日上限）存 `.joycode/memory/`，不写死进脚本/SKILL。
- **停止方式**：`launchctl unload` 卸载定时任务，或用户说「停止托管」。
- **每次自动交易后必须通知用户**，禁止静默下单；任何失败（登录过期/接口错误/余额不足）都通知，不静默。
- **无条件单能力**：模拟交易没有服务端条件单/挂单接口，「自动触发」完全靠本地脚本轮询实现，须如实说明，禁止承诺「服务端后台自动挂单」。

#### claw 参数（必传 · 透传上报，不可假设用户用 JoyCode）

- `sim_autotrade.py` 的 `--claw` 是**必传启动参数**：部署时按用户**实际客户端**填写（如 `codex` / `openclaw` / `joycode`），不得写死或假设。
- 脚本每次调用底层（`jos.py` / `query_sim_contest.py`）都**透传** `--claw`，底层随请求附加 `x-claw` 请求头**上报服务端**，用于统计调用方客户端类型。
- launchd 模板 `scripts/autotrade.launchd.plist` 中以占位符 `__CLAW__` 表示，部署时替换为实际值。

#### 部署指引（三步授权通过后执行）

1. **确认登录态与剩余时长**：`python3 scripts/jos.py token --claw <客户端> --json`，读 `remaining_human` 用大白话告知用户「还能托管约 X」。
2. **先 dry-run 验证**：`python3 scripts/sim_autotrade.py --claw <客户端> --dry-run`，确认登录/行情/策略/降级均正常再正式启动。
3. **部署 launchd 定时任务**：复制 `scripts/autotrade.launchd.plist`，替换占位符 `__CLAW__` / `__PROJECT_DIR__` / `__PYTHON__`，放入 `~/Library/LaunchAgents/`，执行 `launchctl load` 启动；停止用 `launchctl unload`。

## 执行流程

### 登录引导（统一前置）

> 所有需要登录的查询（持仓/收益/早报）在未登录时，按以下流程引导用户。详见 [oauth-integration.md](references/oauth-integration.md)。

**判断是否已登录**：调用 `jos.py token`，退出码 `0` 表示已登录，`2` 表示未登录。**必须先判登录态，禁止凭上下文假设已登录。**

**未登录时——只调用统一入口 `jos.py login-auto`（强制）：**

> 统一执行 `jos.py login-auto`，脚本会自动探测环境并生成授权链接。

**登录三步流程：**

1. **第一步（发起登录）**：执行 `jos.py login-auto`，获取授权链接后**根据终端能力决定呈现方式**：
   - **终端可唤起浏览器**（本地 macOS Agent、Claw 等桌面终端）：直接为用户打开浏览器，跳转到登录页面，无需用户手动复制 URL。
   - **终端无法唤起浏览器**（远端沙箱、SSH、容器等）：对用户说「请点击以下链接完成京东授权：\n{链接}」，由用户手动打开。
2. **第二步（等待用户确认）**：用户在浏览器完成授权后，回调页面会显示一个**「已经登陆成功」**的提示页。用户需要**手动将该提示词复制到对话框中发送**。Agent **必须等待**用户发送该确认消息，**禁止**自动轮询或主动调用 exchange。
3. **第三步（兑换 Token）**：当 Agent 收到用户发送的「已经登陆成功」（或含义等同的确认消息，如「登陆成功」「登录成功了」「已登录」等）后，执行 `jos.py exchange` 兑换 token。兑换成功后对用户回复「登录成功 ✅」并自动续查。

> ⚠️ **关键约束**：
> - **禁止**在未收到用户确认消息时自动调用 exchange 或轮询 auth_status
> - **禁止**对用户说「请告诉我授权是否完成」——回调页已有提示词引导，用户会主动发送
> - 若用户发送的确认消息后 exchange 失败（提示「授权尚未完成」），告知用户「授权似乎尚未完成，请确认已在浏览器完成授权后再试」
> - 若提示「会话不存在或已过期」，说明超时需重新登录

> ⚠️ **脱敏提醒**：`jos.py login` / `exchange` 执行后若输出授权码、token 等凭证，**严禁转述给用户**（详见开头「🔒 安全铁律：授权凭证绝不外露」）；只提示「登录成功 ✅」即可。

**常见登录异常处理：**

| 异常 | 原因 | 处理方式 |
|------|------|----------|
| 授权页 400 Bad Request | 浏览器京东域名 cookie 过多，请求头超限 | 建议用户使用**无痕模式**打开授权链接 |
| 回调页未显示「已经登陆成功」提示 | 授权流程中断或网络问题 | 建议用户刷新页面或重新点击授权链接 |
| exchange 提示「授权尚未完成」 | 用户发了确认但实际授权未完成 | 告知用户「授权似乎尚未完成，请确认已在浏览器完成授权后再试」 |
| 会话不存在或已过期 | 授权会话超时（10 分钟） | 重新执行 `jos.py login-auto` 生成新链接 |

### 持仓/收益

1. 调用统一入口（见 [agent-ops.md](references/agent-ops.md)），将脚本**面向用户的 stdout** 转述给用户。
2. 区分结果类型，**勿混用**：
   - 未登录 ≠ 暂无持仓 ≠ 查询失败
3. 账号不匹配时原样传达「仅支持当前登录账户」，不要改写成「无记录」。
4. **持仓价值计算铁律**：当前持仓价值 = 各银行持仓克重 × **该银行积存金实时金价** 之和。每家银行的金价不同（民生 CMBC-JCJ、兴业 CIB-JCJ0、招行、中信等各自不同），**必须分别按各行金价计算，严禁用京东24h金价（WG-JDAU）统一计算**。脚本已按 bankCode 逐行取价，直接转述其结果即可。
5. 展示时附「数据更新时间」（各行金价报价时间的最新值）。若**部分**银行实时金价取不到，用已取到的某家实时价兜底估算其余银行的持仓价值（缺价行标 `*`、汇总标「（含估算）」、脚注注明估算来源银行），不要只统计取到价的那一家；仅当**所有**银行都取不到时才整体降级：只展示克重/成本/收益等原有字段，不展示价值与更新时间，不报错。

4. 接口失败 → 「查询暂时失败，请稍后重试」，**不要编造排行榜数据**。

### 黄金资讯 / 快讯 / 新闻

1. 用户表述含「黄金资讯」「黄金新闻」「金价新闻」「查看快讯」「黄金快讯」「财经快讯」「最近发生了什么」「最近什么事件影响金价」等 → 一律走本流程（快讯与资讯已合并为同一入口，不再区分）。
2. 无需登录，直接调用资讯脚本 `jdjr_query_news.py`（见 [agent-ops.md](references/agent-ops.md)），传入关键词（默认「黄金」）与条数；脚本已内部合并快讯流与资讯并去重。
3. 按 [references/jdjr-news-search.md](references/jdjr-news-search.md) 与 [references/jdjr-news_output_format.md](references/jdjr-news_output_format.md) 的格式转述，**结尾必带来源标注**。
4. 接口失败 → 「查询暂时失败，请稍后重试」，**不要编造资讯内容**。

**通用规则速查：**
- 红涨绿跌用 emoji（🔴/🟢/⚪），严禁 HTML span 或 ▲▼ 箭头
- 禁止对客展示行情代码（uniqueCode）
- 脚本已渲染为 Markdown 表格+emoji 的输出，直接转述，勿改写
- 持仓价值 = 各银行持仓克重 × **该银行**积存金实时金价（严禁用京东24h金价统一计算）
- 结尾来源标注（`💡 本信息由 [京东金融](...) 提供`）必须原样保留
